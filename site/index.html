    API

    A read-only REST API

    Filter, search and look up cards over /v1. The official instance is free and best-effort: it asks for a client name and allows 30 requests a minute. For production traffic, deploy your own copy on Cloudflare's free plan.

    API reference OpenAPI spec Self-hosting

    Schema

    One file per card, one contract

    Each card is a JSON document in data/{country}/, validated against schema.json in CI and backed by cited issuer sources.

    Fees
    Annual fee, first-year terms, foreign transaction fee
    APR
    Purchase APR range, variable or fixed
    Rewards
    Currency, base rate, category multipliers and caps
    Provenance
    Official sources per card, archived against link rot
    Card art
    Graded card faces with SHA-256 lineage
    {
  "id": "{country}-{slug}",
  "name": string,
  "issuer_id": string,
  "network": "visa" | "mastercard" | "amex" | …,
  "network_tier": "world_elite" | "infinite" | …,
  "status": "active" | "discontinued" | …,
  "annual_fee": { "amount": number, "currency": "USD" },
  "rewards": {
    "base_rate": { "points_per_dollar": number },

  "image": { "url": string | null },
  "sources": [ … ],
  "last_verified": "YYYY-MM-DD"
}

    Contribute

    Adding a card is a pull request

    CI validates the schema, checks your sources and labels the PR. A maintainer reviews the facts before it merges.

    1. Copy the template

      templates/card.template.json into data/{country}/.

    2. Fill it in

      Cite the issuer's own page for every number.

    3. Validate

      npm run validate runs the same checks as CI.

    4. Open a PR

      Or file a card request instead.

    Card art from your own wallet

    On a Mac with your cards in Apple Pay, opencard-export finds the cards the database is missing art for and prepares the PR. It runs entirely on your machine and uploads nothing.

    npx opencard-export
    OpenCard DB
